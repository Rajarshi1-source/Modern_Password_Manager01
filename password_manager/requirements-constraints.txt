# Security-driven transitive pins (Trivy alerts on installed image wheels).
# Keep these as floors (>=) so the resolver can still pick newer patched
# releases when they ship. Lower bounds map to:
#   urllib3   — Trivy #1763 / #1764: CVE chain in <2.7
#   Twisted   — Trivy #1760: CVE in 25.5.0 and earlier
#   pip       — Trivy #1550/#1551/#1553/#1554/#1761/#1762: wheel-install CVEs in <25
#   wheel     — Trivy #1557/#1558: privilege escalation in <0.46.1
#   setuptools — Trivy #1549 chain via jaraco.context: floor <78.1.1. Also
#                ceilinged <81: setuptools 81 removed the `pkg_resources`
#                module, which the legacy cyclonedx-bom (<2) SBOM CLI imports
#                at startup (security.yml SBOM step). Without the ceiling the
#                prod install re-resolves setuptools past 81 and the SBOM step
#                fails with `ModuleNotFoundError: No module named 'pkg_resources'`.
#                DELIBERATE CONFLICT: requirements.txt floors setuptools at
#                >=83.0.0 for PYSEC-2026-3447, and this ceiling overrides that
#                for the prod install (security.yml, which resolves
#                requirements-prod.txt under these constraints), so that
#                install gets 80.x. Accepted because the advisory is an sdist
#                MANIFEST.in exclusion bypass on normalization-preserving
#                filesystems (macOS APFS/HFS+) — it only bites while BUILDING a
#                source distribution, which nothing installed from
#                requirements-prod.txt does. To retire the ceiling and take 83.x, move the SBOM
#                step to cyclonedx-bom>=2 (its CLI dropped the pkg_resources
#                import); do NOT simply raise it, that breaks SBOM generation.
#   jaraco.context — Trivy #1549: path traversal in <6.0.1
#   python-dotenv — Trivy #1556: symlink-follow CVE in <1.1.1 / older system wheel
urllib3>=2.8.0
Twisted>=26.4.0
pip>=25.0
wheel>=0.46.2
setuptools>=84.1.0,<85
